# Governance

Samvev begins as a maintainer-led open-source project.

## Roles

### Maintainer

Maintainers can merge pull requests, manage releases, set repository policy and make final decisions when consensus is not reached. The initial maintainer is the repository owner.

### Contributor

A contributor has submitted accepted code, design, translation, testing or documentation.

### Reviewer

A reviewer is a trusted contributor invited to review a defined area. Review rights do not automatically grant release or security access.

## Decision making

1. Prefer documented consensus in issues and pull requests.
2. Use architectural decision records for durable technical or product decisions.
3. Record meaningful objections and trade-offs rather than erasing disagreement.
4. The maintainer makes the final decision when progress is blocked.
5. Security and privacy concerns may override convenience or feature scope.

## Project direction

The project commits to:

- complete self-hosted core functionality
- public development by default
- optional paid hosting based on operational convenience
- a contribution path for non-programmers
- multilingual and accessible interfaces
- no hidden collection of household data

## Future evolution

When multiple long-term maintainers emerge, governance may evolve toward area ownership, release teams and documented voting or consensus rules. Such changes require an architectural decision record and public discussion.
