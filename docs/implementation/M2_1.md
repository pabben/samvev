# M2.1 AI provider foundation

2026-09-08 UTC. **Local implementation and targeted validation passed. Git
delivery is blocked by the sandbox's read-only `.git` mount.**

## Delivered

- Provider-neutral tasks/results for `generate`, `extract`, `classify` and
  `plan`, with source evidence, timestamps and uncertainty. The server runner
  checks enabled/configuration state, selects routine/strong models and logs usage.
- OpenAI Responses adapter with configured model identifiers, normalized errors,
  `store: false`, bounded requests and no retries or automatic routing.
- Household-admin AI settings in English and Norwegian Bokmål: enable/disable,
  provider status, routine/strong models, write-only credential, explicit tests
  and usage totals/recent activity. Ordinary members cannot access these settings.
- Server-side AES-256-GCM credential storage; admin/session/CSRF/origin checks,
  household isolation, revision conflicts and a durable limit of ten connection
  tests per household per hour. No prompt/output content is stored in usage.
- Versioned ChatGPT bridge request/result contracts with task/idempotency IDs.
  Future OpenAI-compatible adapters receive base URL, model and optional key;
  their implementation and admin configuration are deferred to M2.2.

No weekly-plan monitor, Gemini adapter or other integration was implemented.
See [ADR 0012](../decisions/0012-ai-provider-foundation.md).

## ChatGPT subscription feasibility: PARTIAL

The completed 2026-09-07 spike is retained, without another investigation.
[ChatGPT Tasks can use plugins](https://learn.chatgpt.com/docs/automations), but
[connecting a private MCP service](https://developers.openai.com/plugins/deploy/connect-chatgpt)
requires supported connectivity (authenticated HTTPS or Secure MCP Tunnel) and
the relevant account/workspace access. No authenticated Samvev connection is
configured or demonstrated here. This is an installation/account validation gap,
not a claim that the platform universally forbids the integration.

Subscription mode therefore shows **unavailable**. This slice supplies contracts,
not a callable MCP/message/task ingress. It does not automate web sessions or
cookies, and an OpenAI API credential does not represent a ChatGPT subscription.

**Integration validation follow-up M2-AI-01 (open):** validate an actual supported
ChatGPT account/connection and a scheduled tool call with scoped authorization
and replay protection before enabling the bridge. Also validate configured
OpenAI models with a real API credential; no paid provider request was made here.
The adapter currently caps output at 64 tokens and the full response at ten
seconds. A model that does not complete within those bounds reports failure;
compatibility with every configured model is not claimed.

## Runtime, migration and rollback

Open <http://127.0.0.1:4173> using a synthetic household administrator from the
[M1 demo](M1_DEMO.md), then choose AI settings. AI remains disabled after testing.
An explicit connection test may use API credits even while AI is disabled.

Migration `005_ai_provider_foundation.sql` adds `ai_settings` and
`ai_usage_events` without changing M1 tables. It was applied using
`docker compose -p samvev-m1 -f compose.yaml run --rm --no-deps migrate`;
only the local app was restarted to build/load the changes.

Back up the database and `.local/ai-master-key` together, outside Git. The key is
created lazily when the first credential is saved. Losing it requires re-entering
credentials. For code rollback, the previous M1 application can ignore these
additive tables; retain them and the key for recovery. No rollback or destructive
schema removal was performed.
