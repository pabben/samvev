# M2.3 general AI tasks and source monitors

2026-09-08 UTC. M2.3 adds the first general task/monitor slice on top of the M1 message lifecycle and M2 provider boundary.

## Behavior

Household administrators can create a draft from a plain-language instruction containing one explicit public URL or domain, or provide a manual source override. Samvev normalizes and shows that source before approval. AI interpretation is stored as a visible structured rule. A separate approval by an authorized administrator activates the task and records that approver as its execution authority; editing returns it to draft.

Draft and paused tasks can be tested immediately through the production fetch/AI validation pipeline without activation, schedule changes, fingerprint changes or messages. Active tasks can run immediately without moving their next scheduled check. An unchanged source reuses the last confirmed result and skips AI. A stronger-quality preview is similarly side-effect free, after which the internal quality preference can be retained explicitly for future runs. Editing keeps run history but clears the current result and event projection so an old answer cannot appear under a newly approved rule.

Pausing withdraws generated live/future messages. Resuming schedules a fresh source analysis so only current findings are restored. A task is also paused automatically if its approving account is disabled or loses the message/display permissions required by its configured recipients.

The worker claims due tasks with a restart-safe lease. Samvev performs all source
network access and gives the model one provider-independent `web.open` tool. The
model can open the approved root and exact same-origin links returned by earlier
calls, then select the content that answers the request. Interpretation, Test
now, Run now, stronger preview and scheduled runs share the same bounded runner.
The provider never receives uncontrolled general network, shell or file access.

A successful production run stores a fingerprint manifest for every fetched
document that contributed to the run. Samvev refreshes these documents with
ordinary code before later analysis. AI runs only if at least one dependency
changed; a fully unchanged manifest records the check with zero model calls.
Source checks, actual provider turns and unchanged skips are counted without
storing prompts, raw source content, model output or reasoning in usage logs.

Validated future events retain date/time, type, description, actions, people, an exact source quote, source URL, confidence and uncertainty. General answer tasks retain the answer, exact quote, source URL, confidence and uncertainty in household-protected run history. Answer text and message-bearing event fields must be source-extractive and supported by the exact evidence before acceptance. Stable event mappings create, update or withdraw the existing M1 scheduled message and its person/display targets without a parallel delivery engine.

Monitor targets use the same message capabilities and per-membership display
grants as ordinary messages. The approving membership remains authoritative for
scheduled and manual production runs; loss of those rights pauses the task before
source or AI work. Interpretation and manual AI actions are durably rate limited,
and task leases serialize concurrent work for one revision.

Provider policies are `default`, `local` and `openai`. The latter two require the household's currently configured provider to match. Automatic local-to-paid fallback is deliberately absent.

## Source security and limits

Monitor sources allow public HTTP/HTTPS only. URL user information and
credential-like query parameters, loopback, private/LAN, link-local, metadata
and reserved destinations are blocked. Ordinary query parameters remain
available. Every followed redirect is validated and DNS results are checked and
pinned. Requests send no household credentials or cookies, use a 15-second
network/DNS deadline, allow at most three redirects and accept only HTML/XHTML
or text-based PDF responses up to 5 MiB. PDF extraction checks the deadline
between parser operations and is limited to 40 pages and 250,000 normalized
characters. Scanned/image-only and unsupported PDFs fail visibly.

The tool loop validates a complete batch before the first fetch and allows at
most six executions across seven provider turns. URLs must be the approved root
or an exact previously returned same-origin link; followed redirects keep that
origin. Each tool result is limited to 16 KiB, including at most 8 KiB of text
and separately bounded title, headings and ranked links; aggregate tool context
is limited to 96 KiB. One outer
180-second deadline covers dependency refresh and AI/tool work, below the
four-minute lease. The browser allows 210 seconds for a manual action. A
source-based analysis cannot finish before at least one successful `web.open`;
premature provider answers are retried within the existing seven-turn bound.
Source text is marked as untrusted data so instructions in a page cannot widen
tool policy.

Unlike the local AI provider, monitor URLs cannot target LAN services. This prevents the admin feature from becoming an arbitrary internal fetch proxy.

## Migration and rollback

Migration `007_monitor_tasks.sql` is additive. It creates tasks, normalized recipient relations, run metadata and event/message mappings. Migration `011_monitor_manual_runs.sql` additively records scheduled/test/manual/smarter run kind plus validated result kind, result and final source URL. Migration `012_monitor_agent_tools.sql` additively records dependency manifests, actual AI-turn counts and compact tool provenance, and creates a tool-audit table. Code rollback can leave these columns unused. Before a destructive schema rollback, pause monitors and retain the data until scheduled messages have been reviewed; deleting a task withdraws its future generated messages.

All fixtures and test accounts are synthetic. No real household, school, child, credential or source data is included.

## Provider-independent web-tool follow-up

The provider contract now supports request-local sessions that return either a
final response or strict function calls. OpenAI Responses and OpenAI-compatible
Chat Completions map to the same Samvev turn contract. Existing one-shot calls
and connection tests remain compatible, including keyless local providers,
reasoning effort and timeout/error classification. Provider adapters use
request-local wire-safe aliases for internal tool names and fail closed on an
unknown or colliding alias. Local-compatible DNS, HTTP and body parsing share
one timeout budget.

Normal Oppdrag UI still contains no provider, model, reasoning or tool terms.
Results link to the exact evidence document and can disclose several sanitized
sources with their fetch times. Norwegian Bokmål and English distinguish a
source timeout, an unavailable/blocked source and a bounded exploration failure.
The browser waits 210 seconds, slightly longer than the server's total deadline.

Successful and failed tool activity is audited separately. Failure records keep
only the allowlisted tool name, a fully validated attempted URL, outcome and a
normalized error code; raw arguments, content and fingerprints are omitted.
Invalid or credential-bearing calls are rejected before their URL can be
persisted. A final source answer without a successful source document, and an
interpretation that claims Samvev lacks web access, are rejected instead of
being shown or stored as successful results.
