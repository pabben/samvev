# M2.3 general AI tasks and source monitors

2026-09-08 UTC. M2.3 adds the first general task/monitor slice on top of the M1 message lifecycle and M2 provider boundary.

## Behavior

Household administrators can create a draft from a plain-language instruction containing one explicit public URL or domain, or provide a manual source override. Samvev normalizes and shows that source before approval. AI interpretation is stored as a visible structured rule. A separate approval by an authorized administrator activates the task and records that approver as its execution authority; editing returns it to draft.

Draft and paused tasks can be tested immediately through the production fetch/AI validation pipeline without activation, schedule changes, fingerprint changes or messages. Active tasks can run immediately without moving their next scheduled check. An unchanged source reuses the last confirmed result and skips AI. A stronger-quality preview is similarly side-effect free, after which the internal quality preference can be retained explicitly for future runs. Editing keeps run history but clears the current result and event projection so an old answer cannot appear under a newly approved rule.

Pausing withdraws generated live/future messages. Resuming schedules a fresh source analysis so only current findings are restored. A task is also paused automatically if its approving account is disabled or loses the message/display permissions required by its configured recipients.

The worker claims due tasks with a restart-safe lease. It fetches and normalizes the source with ordinary HTTP, selects lines matching the approved event types, keywords or people plus adjacent context, and hashes the same bounded 20,000-character relevant view that AI receives. AI runs only when this fingerprint differs from the last successfully processed version, so unrelated page chrome changes are ignored. Source checks, AI calls and unchanged skips are counted without storing prompts or provider output in usage logs.

Validated future events retain date/time, type, description, actions, people, an exact source quote, source URL, confidence and uncertainty. General answer tasks retain the answer, exact quote, source URL, confidence and uncertainty in household-protected run history. Answer text and message-bearing event fields must be source-extractive and supported by the exact evidence before acceptance. Stable event mappings create, update or withdraw the existing M1 scheduled message and its person/display targets without a parallel delivery engine.

Monitor targets use the same message capabilities and per-membership display
grants as ordinary messages. The approving membership remains authoritative for
scheduled and manual production runs; loss of those rights pauses the task before
source or AI work. Interpretation and manual AI actions are durably rate limited,
and task leases serialize concurrent work for one revision.

Provider policies are `default`, `local` and `openai`. The latter two require the household's currently configured provider to match. Automatic local-to-paid fallback is deliberately absent.

## Source security and limits

Monitor sources allow public HTTP/HTTPS only. URL credentials, loopback, private/LAN, link-local, metadata and reserved destinations are blocked. Every followed redirect is validated and DNS results are checked and pinned. Requests send no household credentials or cookies, use a 15-second network/DNS deadline, allow at most three redirects and accept only HTML/XHTML or text-based PDF responses up to 5 MiB. PDF extraction checks the deadline between parser operations and is limited to 40 pages and 250,000 normalized characters. Scanned/image-only and unsupported PDFs fail visibly.

Unlike the local AI provider, monitor URLs cannot target LAN services. This prevents the admin feature from becoming an arbitrary internal fetch proxy.

## Migration and rollback

Migration `007_monitor_tasks.sql` is additive. It creates tasks, normalized recipient relations, run metadata and event/message mappings. Migration `011_monitor_manual_runs.sql` additively records scheduled/test/manual/smarter run kind plus validated result kind, result and final source URL. Code rollback can leave these columns unused. Before a destructive schema rollback, pause monitors and retain the data until scheduled messages have been reviewed; deleting a task withdraws its future generated messages.

All fixtures and test accounts are synthetic. No real household, school, child, credential or source data is included.
