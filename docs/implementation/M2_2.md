# M2.2 local OpenAI-compatible provider

2026-09-08 UTC. Local implementation and targeted validation passed. Git
delivery remains outside this sandbox because `.git` is read-only.

## Delivered

- An `openai_compatible` adapter implements the existing `generate`, `extract`,
  `classify` and `plan` contract through Chat Completions. It supports a custom
  API base URL, routine/strong models, an optional API key, a 30-second total
  timeout, bounded responses, normalized failures and optional token usage.
- Household administrators can select OpenAI or Local / OpenAI-compatible, save
  the local URL and models, manage a write-only optional credential, test either
  model tier and see provider status. English, Norwegian Bokmål, mobile and dark
  mode are covered. Ordinary members cannot see or call these settings.
- Credentials remain in the existing server-side AES-256-GCM vault. Provider or
  local endpoint changes clear an old credential unless a replacement is sent.
  Usage records contain metadata and token counts only, never prompts or output.
- Localhost and LAN are intentionally supported. HTTP(S) endpoint validation
  blocks URL credentials, query/fragment components, known metadata targets,
  link-local, unspecified and multicast addresses. DNS is checked per request,
  the validated address is pinned to the connection and redirects are not
  followed.

ChatGPT Tasks/MCP feasibility remains **PARTIAL** exactly as in M2.1. No weekly
plan, website monitor, scheduling, provider fallback or paid AI request is part
of M2.2. The configured endpoint must expose OpenAI-compatible
`/chat/completions`; for example, a base ending in `/v1` receives requests at
`/v1/chat/completions`. From Docker, `localhost` names the Samvev API container,
so a host or separate container normally needs a reachable LAN/network name.

## Migration and rollback

Migration `006_openai_compatible_provider.sql` adds only nullable `base_url` to
`ai_settings`. Older M2.1 code can ignore the column, so code rollback does not
require destructive schema changes. Keep the database and AI master key backed
up together. A credential deliberately cleared by a provider/endpoint change
must be entered again.
