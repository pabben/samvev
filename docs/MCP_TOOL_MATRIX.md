# MCP tool and domain-operation matrix

Status: documentation snapshot of baseline commit `f79271c` (2026-11-25). MCP endpoint and tools in the implementation column are provisional until the backend change is merged and validated. The planned public endpoint is `https://samvev.pabben.org/mcp`; it is not deployed or verified.

This matrix separates operations already available through Samvev's UI/API from operations exposed by MCP. “Capability” names are enforced server-side by the current API/service; an MCP client must not receive more authority than its authenticated Samvev identity. See [users and permissions](USERS_AND_PERMISSIONS.md) and [AI tasks and notifications](AI_TASKS_AND_NOTIFICATIONS.md).

| Domain and user operation | Existing API/service surface | Required capability today | MCP status / safety boundary |
|---|---|---|---|
| Household context and Home overview: read | `GET /api/v1/households/:householdId/home`, `/dashboard`; home service in `services/api/src/app.ts` | `household.view` | `samvev_context` planned read-only. Filter to the authenticated household and fields the caller can see. |
| Monitor tasks: list/read | `GET /api/v1/households/:householdId/monitors`, `.../:monitorId/runs/:runId`; monitor service | `household.manage` | `samvev_monitors_list` planned read-only. No run history/tool until explicitly added. |
| Monitor tasks: create/update/delete, approve, pause/resume, run/interpret, review results | `POST/PATCH/DELETE /api/v1/households/:householdId/monitors...`; `services/api/src/app.ts` and monitor services | `household.manage` | Planned only. Recurring source access, activation, and manual runs require an explicit user confirmation step; no mutation tool in first milestone. Existing app uses explicit approve and lifecycle controls. |
| People and memberships: read/create/update; account and invitation administration | `GET/POST /api/v1/households/:householdId/people`; `PATCH .../people/:personId`; membership/account routes; `services/api/src/app.ts` | `household.view` to read; `people.manage` for another person's profile; `account.manage` for accounts; household/installation administration for memberships and grants (check route/service) | Not exposed. Any future read must not reveal child/private profile fields beyond server grants. Creation, account changes and invitations are administrative actions. |
| Messages: list/read/create/update/withdraw | `GET/POST /api/v1/households/:householdId/messages`; `PATCH .../messages/:messageId`; `POST .../:messageId/withdraw` | `household.view`; create requires `message.create.household`; future publish time also requires `message.schedule`; editing another member's item requires `message.manage.household`; display audience requires `message.publish.display` | Not exposed. Message creation/publication, changing audience or schedule, and withdrawal require explicit confirmation. Respect recipient/display validation and existing revision/idempotency checks. |
| Groceries, dinner options, dinner plan: read/create/update/delete/assign | `GET/POST/PATCH/DELETE /api/v1/households/:householdId/groceries`, `/dinner-options`; `GET /dinners`, `PUT /dinners/:localDate`; `householdBoards` in `services/api/src/app.ts` | `household.view` plus actor/resource-level checks in `householdBoards` | Not exposed. Writes need explicit confirmation and must use actor/resource checks. |
| Calendars: read connections/events; create connection; configure, sync, disconnect/delete | `/api/v1/households/:householdId/calendar-connections...`; calendar service in `services/api/src/calendar/service.ts`; event reads under `/activities` and `/events` | `household.view` for many connection operations; some settings require `household.manage`; connector and source ownership rules also apply | Not exposed. Private calendar data and source URLs are sensitive; connection, schedule, sync, revoke, and delete actions require explicit confirmation. Never return credentials or subscription secrets. |
| Integrations and credentials: list/create/update/revoke | `/api/v1/households/:householdId/integrations...`; integration services in `services/api/src/app.ts` | `household.manage` for household connection administration; integration-scoped credentials also enforce their granted capabilities | Not exposed. Credential values are never readable; connect/revoke or credential lifecycle changes need explicit confirmation. |
| Display setup, pairing, grants and policy: read/manage | `/api/v1/households/:householdId/displays...`, `/display-setups...`, board grants; `services/api/src/app.ts` | `display.manage`; specific grant routes additionally enforce board/privacy policies | Not exposed. Pairing, grants, and disclosure changes need explicit confirmation. MCP must never impersonate a display account or broaden its projection. |
| Home Assistant controls and actions | `/api/v1/households/:householdId/home-assistant/controls...`; `services/api/src/ha-bridge/service.ts` and control service | household authorization plus entity/action grants; control dispatch confirmation/revision checks | Not exposed. Physical or automation actions stay out of MCP until each is allowlisted and guarded by explicit confirmation. |
| AI provider settings, ChatGPT connection, usage | `/api/v1/households/:householdId/ai/...`; AI admin services in `services/api/src/app.ts` | `household.manage` | Not exposed. Never expose provider credentials, OAuth tokens, raw prompts, or connection helper secrets. Configuration and disconnection need confirmation. |
| Generic external intelligence items: read/create/delete | `/api/v1/integrations/items...`; external intelligence service in `services/api/src/app.ts` | integration-authenticated, household-scoped credential and per-operation policy | Not exposed. External credentials are not MCP identity; retain source, timestamp and uncertainty. |

## MCP boundary at this milestone

| MCP tool | Intended operation | Status |
|---|---|---|
| `samvev_context` | Read a minimal, caller-authorized household context | Planned for first backend milestone; not verified in this baseline |
| `samvev_monitors_list` | List monitor tasks the authenticated user may view | Planned for first backend milestone; not verified in this baseline |
| All other operations above | Read or mutate their corresponding domain | Not exposed; future design and authorization review required |

The planned MCP transport is `/mcp` with OAuth metadata. Neither endpoint reachability, OAuth interoperability, scheduled client invocation, nor end-to-end behavior is established by this baseline. Do not infer that an operation is MCP-capable because its API route exists.
